# Mahoraga 7 main stabilization — 2026-09-01

## Scope

This record covers PR #77, `fix/stabilize-main-20260901`, which repairs the post-PR-#76 autonomous-action regression and strengthens repository truth without modifying the self-evolution stack.

## Pre-fix failure

GitHub `Verify Mahoraga` run #152 on PR #76 failed on both Windows and Ubuntu after the PR reported a local passing suite. Windows reached 405 tests with 404 passing and one failure:

`test/chat-runtime.test.mjs` -> `TypeError: Codex Builder base commit is invalid.`

Root cause: conversation autonomy emitted `codex.execute` objective children without the immutable base, integration lease, writable paths, task-policy derivation, and PREPARED Codex Builder session required by the existing execution-cell contract.

## Stabilization implementation

PR #77 keeps the six-stage autonomous graph and adds:

- deterministic candidate write-scope derivation;
- fixed-boundary repository HEAD capture;
- immutable base/path binding on Codex objective definitions;
- runtime-installed objective-release authority;
- server-derived task policy for objective children;
- bounded Primary Local integration leases at child-release time;
- contention behavior that waits instead of bypassing another Primary;
- PREPARED Codex Builder sessions before dispatch;
- fresh objective-owned leases between completed Codex stages;
- pre-vault scope derivation for new encrypted conversations;
- immutable repair-baseline coverage for the new authority modules;
- host-portable Codex package-fallback test fixtures so Linux CI verifies the same production discovery contract without a fabricated Windows absolute path.

## Self-evolution exclusion

This stabilization intentionally leaves the self-evolution stack unchanged. It does not modify:

- `src/evolution-controller.mjs`;
- evolution-controller test/contracts;
- candidate build/deploy/canary/activation/rollback semantics;
- update authority in `mahoraga.manifest.json`.

Canonical evolution tests remain in CI as regression checks.

## GitHub branch-protection limitation

`main` was observed unprotected with no required status checks before this work. The connected GitHub interface used for this stabilization provides branch/ruleset inspection but no settings mutation action for enabling branch protection. No repository-file substitute is presented as equivalent enforcement.

Until GitHub branch protection is changed through a settings surface with write support, the operational merge rule is: do not merge unless both hosted platforms are green for the exact PR head.

## Live Windows boundary

This record proves repository behavior only. It does not prove the version/process currently active on the Windows host. A separate read-only live-machine audit is required for active PID, loopback listener, runtime version, workers, provider readiness, canaries, and operational database state.
