# Adaptive evolution policy

Mahoraga may grow across model, conversation, connector, telemetry, and agentic execution capabilities, but growth is promoted through evidence rather than unrestricted runtime mutation.

## Approved cloud lane

Authenticated ChatGPT Work Codex may operate entirely through the GitHub cloud connection. It may inspect the repository, create a bounded feature branch, write code and tests, open a pull request, observe exact-head CI, and complete an owner-authorized merge/deployment. This lane does not require a connection to an owner PC.

## Capability expansion rules

1. **Multi-model fabric:** add providers through the existing route registry and model supply-chain admission process. Model identity, cost class, data class, health, and immutable artifact evidence stay explicit.
2. **Complex conversations:** preserve conversation lineage through the existing conversation gateway, bounded memory, content-vault, and receipt contracts. Do not infer durable authority from conversational drift.
3. **Universal connectors:** normalize external events through explicit adapters. Each adapter declares protocol, capability, data class, credential boundary, timeouts, and receipts.
4. **Adaptive code:** generate candidates only inside an isolated candidate root. Static inspection, focused behavior tests, baseline preservation, required CI, and review precede promotion.
5. **Telemetry:** publish only observed measurements with source and freshness. Unknown state stays unknown; simulation must be labeled and cannot authorize action.
6. **Network expansion:** listeners bind to an approved boundary, authenticate every peer, validate destinations, rate-limit traffic, and remain removable. No caller-selected executable paths or unrestricted supervisor shell.

## Fixed restrictions

The following shortcuts are prohibited even when they appear faster:

- bypassing `npm run verify` or protected checks;
- using `eval`, `new Function`, or dynamically generated executable source in an authoritative runtime;
- writing directly to the authoritative source tree from a running process;
- treating a fallback string such as `SANDBOX` as a secret;
- fabricating memory pointers, drift scores, model counts, network peers, or online status;
- disabling durability controls such as SQLite synchronization in production;
- opening arbitrary external network listeners or sending private content without explicit adapter and data-class authority;
- silently enabling paid model fallback or spending credits outside the selected lane.

## Promotion evidence

A candidate is promotable only when its exact head has:

- focused tests for the affected behavior;
- required repository CI;
- no unexplained baseline deletion or rename;
- a reviewable diff and rollback path;
- truthful deployment/runtime provenance;
- owner or repository-policy authority for merge and deployment.

The browser cockpit mirrors this policy: it distinguishes a healthy published shell from a paired execution core and displays verified routes instead of simulated activity.
