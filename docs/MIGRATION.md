# Migration sequence

## Phase 1 — completed in this foundation

1. Establish one canonical manifest.
2. Move process ownership from PowerShell/WPF into a persistent Node supervisor.
3. Add SQLite durability, task leases, recovery, worker heartbeats, and restart.
4. Add a localhost cockpit and rollback-protected automatic improvement decisions.

## Phase 2 — local capability workers

1. Migrate the existing Excel adapter without widening its workbook boundary.
2. Add a repository worker with branch, diff, test, and candidate-commit support.
3. Add a file worker with workspace roots and explicit operation contracts.
4. Add browser DOM automation and a Windows UI Automation worker as separate
   processes. Visual computer control remains the final fallback.
5. Enable LM Studio only after model availability, response-schema, tool-call,
   timeout, and cancellation probes pass.

## Phase 3 — Microsoft plane

1. Create an owner-controlled Dataverse or SharePoint task queue.
2. Connect Microsoft Graph for direct operations and Microsoft 365 Copilot for
   enterprise reasoning.
3. Give General Mahoraga queue/status tools and connect specialist agents.
4. Keep cloud-to-PC work outbound-only from the local worker.
5. Run synthetic end-to-end tests before publishing any revised Studio agent.

## Phase 4 — improvement engine

1. Cluster repeated failure codes.
2. Create a candidate branch and regression test.
3. Run isolated and full verification.
4. Present the diff, evidence, and rollback path.
5. Wait for the user's greenlight; activation remains a separate explicit action.
